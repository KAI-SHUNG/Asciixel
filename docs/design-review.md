# 核心设计审查记录

日期：2026-09-22。对象：对话中提出的像素→ASCII 方案。范围：设计与首版目标，不是实现代码审查。

## 结论

保留“完整字符单元 alpha 覆盖率标定 + 图像分块面积加权均值 + 最近密度匹配”作为首版路线。原方案方向可行，但亮度语义、终端与字体标定的一致性、时间状态和数据所有权需要明确后才能实施。修订已写入 [设计文档](design.md)。

## 发现与处理

| 级别 | 问题 | 修订 |
| --- | --- | --- |
| 重要 | alpha 覆盖率与实际显示亮度被隐含等同 | 规定线性 RGB 及线性合成前提，终端仅近似预览 |
| 重要 | 字体名无法唯一确定密度，字符包围盒归一化会失真 | 完整单元格、统一基线，缓存键包含字体内容、字号、布局和栅格化参数 |
| 重要 | 只说字形居中/大小不足以避免裁切与比例偏差 | 固定原点并容纳全部候选边界，实际尺寸参与网格比例 |
| 重要 | ASCII 最密字符不能表示满亮度 | 分离密度铺满与亮度保真，明确饱和与绝对亮度压缩 |
| 重要 | 终端无法保证使用标定字体及渲染参数 | README 和设计明确近似边界，未来自有渲染器共享 atlas |
| 重要 | FFmpeg 与 FreeType 原生对象可能污染算法边界 | 拥有型项目数据、适配器内 RAII，定义元数据与缓冲生命周期 |
| 重要 | 视频迟滞未定义量纲、重置及跳帧行为 | 以覆盖率为单位定义迟滞，仅已显示帧更新历史，规定重置条件 |
| 重要 | 仅按 PTS 播放未覆盖缺失/异常时间戳及延迟帧 | 定义回退时长、单调调度、EOF 排空与末帧显示 |
| 次要 | 95 个字符可能缺字或具有相同密度 | 缺字报错，密度及码点确定性排序与平局规则 |
| 次要 | 后续空间匹配公式缺少验证，容易扩大首版 | 仅预留特征扩展点，不冻结公式，不纳入首版 |

## 文档复审与补充

此前独立审阅补充了时间轴锚定、过期区间、profile 布局和空格 advance 检查，但“未发现其他阻碍实施的重要问题”的结论遗漏了用户操作契约和字体布局初始化，应以下列补充为准。

| 反馈 | 判断与落实 |
| --- | --- |
| CLI 配置未定义 | 成立；设计 3.1 和 README 补齐参数、默认值、范围、冲突、输出文件策略和退出码；错误信息结构固定，措辞不逐句冻结 |
| 自动列数与指定列数矛盾 | 两者可共存，原文未同步范围；首版 terminal 默认 auto、TXT 默认 120，TXT 显式 auto 报错 |
| 终端容量标准缺失 | 补齐尺寸查询责任、可见区域、预留一行一列、失败及缩小策略；容量直接比较字符行列，不进行像素换算 |
| 字体单元格初始化循环 | 将 FontConfig 改为输入 FontRequest 和派生 RasterizedFont/CellGeometry；字体适配器保存一次栅格化结果后统一排布，Builder 仅组织分析及缓存 |
| TXT 行尾不明确 | 固定 UTF-8 无 BOM、每行 LF、末行 LF、保留尾随空格；Windows 避免自动 CRLF 转换 |
| 透明背景来源缺失 | 应用统一解析 ResolvedTheme，合成、映射、输出共享同一前背景；不添加独立背景配置 |

同时澄清静态终端图片留在普通屏幕、视频使用替代屏幕，避免图片输出完成后立即消失。本轮为文档修订与一致性检查，未进行功能测试。

## 本次不评价的事项

- 编码器、音频、GPU、GUI、彩色模式和空间特征效果：明确在首版之外。
- 性能指标和字体视觉优劣：尚无实现或固定测试机器，不能声称达到某一帧率或画质。
- 编译、单元测试结果：仓库尚无实现，本次只验证文档内容及引用一致性。
